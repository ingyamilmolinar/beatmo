# Phase 0 — Kill suffix semantics Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make no code path parse an instrument id, so the `-N` suffix stops
carrying three colliding meanings — without changing a single rendered sample.

**Architecture:** Every place that currently *infers* a relationship from an
id's spelling is replaced by an explicit table. Loudness folding becomes a
declared alias map; the 18 shipped `-N` variants get descriptive slugs with
registry-level aliases for old saves; instance ids move to a `--N` form that
cannot collide with a shipped id; and both stray `baseInstrumentID` helpers
are deleted.

**Tech Stack:** Go 1.26 (bundled at `.tools/go/bin/go`), the `-tags test`
stubbed-Ebiten fast path, `cmd/gen-showcase` for templates,
`go generate ./internal/audio/` for the roster.

**Spec:** `docs/superpowers/specs/2026-09-12-uuid-sound-library-design.md`
(this plan implements Phase 0 only)

## Scope note

The spec has five phases. This plan covers **Phase 0 alone**, which is
independently shippable and leaves the app fully working. Phases 1–4 (one
struct, UUID identity, reference join, adopt mints Sounds) each get their own
plan, written after this one lands — a single bite-sized plan across all five
would be unreviewable, and each phase's design decisions depend on the state
the previous one leaves behind.

### Task 1: Replace suffix-based loudness folding with a declared alias map

`baseInstrumentID` is **not** dead indirection — it feeds
`normalizeAndScale(buf, baseInstrumentID(id))` →
`ConfigForInstrument(...).Amplitude`. Measured today, 17 of 22 variants
resolve to a *different* amplitude folded vs unfolded, because
`instrument_loudness_gen.go` (generated by `cmd/measure-loudness`, 110 base
entries) has no variant rows and `ConfigForInstrument` falls back to
`DefaultAmplitude` 0.8. Deleting the fold naively makes `fm-bell-1` jump from
0.4473 to 0.8 — nearly twice as loud.

So the fold is preserved as an **explicit table** instead of string parsing.
This is a refactoring task: the test locks current behavior *before* the
change.

**Files:**
- Modify: `src/go/internal/audio/loudness_amp.go`
- Modify: `src/go/internal/audio/synth_recipe_dispatch.go:245,264,366,464,523`
- Test: `src/go/internal/audio/loudness_alias_test.go` (create)

**Interfaces:**
- Consumes: nothing from earlier tasks.
- Produces: `loudnessAliasFor(id string) string` — returns the id whose
  measured loudness `id` borrows, or `id` itself. Task 3 renames its keys.

```go
//go:build !js

package audio

import "testing"

// Every shipped variant borrows its BASE instrument's measured loudness.
// That is a deliberate decision, not a consequence of how the ids are
// spelled: instrument_loudness_gen.go carries base rows only, so a variant
// left to itself falls back to DefaultAmplitude (0.8) and jumps in level --
// fm-bell-1 would go 0.4473 -> 0.8, nearly twice as loud.
//
// These values are MEASURED from the tree before the suffix fold was
// removed. They are the definition of "Phase 0 changed no audio".
func TestVariantsBorrowTheirBaseLoudness(t *testing.T) {
	for _, tc := range []struct {
		id   string
		want float32
	}{
		{"snare-1", 1.0000}, {"snare-2", 1.0000},
		{"kick-1", 1.0000}, {"kick-2", 1.0000},
		{"hihat-1", 1.0000}, {"hihat-2", 1.0000},
		{"tom-1", 0.5031}, {"tom-2", 0.5031},
		{"clap-1", 1.0000}, {"clap-2", 1.0000},
		{"cowbell-1", 0.7186}, {"cowbell-2", 0.7186},
		{"fm-bass-1", 0.5160}, {"fm-bell-1", 0.4473},
		{"fm-lead-1", 0.4648}, {"fm-epiano-1", 0.5208},
		{"fm-pluck-1", 0.7572},
	} {
		if got := ConfigForInstrument(tc.id).Amplitude; got != tc.want {
			t.Errorf("%s amplitude = %.4f, want %.4f", tc.id, got, tc.want)
		}
	}
}

// The four "expressive dynamics" variants were never folded: they carry no
// -N suffix, so they already used DefaultAmplitude. Pinned so a later phase
// cannot quietly fold them in.
func TestExpressiveVariantsUseTheirOwnLoudness(t *testing.T) {
	// sub-bass-1 belongs here, not with the borrowers: sub-bass itself has no
	// measured loudness, so both already fall back to DefaultAmplitude and an
	// alias row would point at nothing.
	for _, id := range []string{"sub-bass", "sub-bass-1", "snare-ghost", "kick-tight", "hihat-pedal", "clap-tight"} {
		if got := ConfigForInstrument(id).Amplitude; got != 0.8000 {
			t.Errorf("%s amplitude = %.4f, want 0.8000", id, got)
		}
	}
}
```

- [ ] **Step 3: Add the declared alias map**

In `src/go/internal/audio/loudness_amp.go`, above `loudnessAmp`:

```go
// loudnessAliases declares which instruments borrow another instrument's
// MEASURED loudness. cmd/measure-loudness records base instruments only, so
// every shipped variant needs a row here or it silently falls back to
// DefaultAmplitude -- fm-bell-1 would render at 0.8 instead of 0.4473.
//
// Seventeen rows, not eighteen: sub-bass-1 is absent because sub-bass has no
measurement either, so the pair already shares DefaultAmplitude.
This replaces a string-suffix strip ("-1"/"-2" chopped off the id). The
// table says the same thing the strip used to infer, except it is reviewable,
// it cannot misfire on an id that merely ends in a digit (bass-808), and a
// new variant that forgets to appear here fails TestEveryVariantDeclaresItsLoudness
// instead of quietly getting louder.
var loudnessAliases = map[string]string{
	"snare-1": "snare", "snare-2": "snare",
	"kick-1": "kick", "kick-2": "kick",
	"hihat-1": "hihat", "hihat-2": "hihat",
	"tom-1": "tom", "tom-2": "tom",
	"clap-1": "clap", "clap-2": "clap",
	"cowbell-1": "cowbell", "cowbell-2": "cowbell",
	"fm-bass-1": "fm-bass", "fm-bell-1": "fm-bell",
	"fm-lead-1": "fm-lead", "fm-epiano-1": "fm-epiano",
	"fm-pluck-1": "fm-pluck",
}

// loudnessAliasFor returns the id whose measured loudness id borrows, or id
// itself when it has its own measurement.
func loudnessAliasFor(id string) string {
	if base, ok := loudnessAliases[id]; ok {
		return base
	}
	return id
}
```

Then make `loudnessAmp` consult it. Replace the body:

```go
func loudnessAmp(id string) (float32, bool) {
	if v, ok := runtimeLoudnessAmp.Load(id); ok {
		return v.(float32), true
	}
	if v, ok := instrumentLoudnessAmp[id]; ok {
		return v, true
	}
	// Declared borrow (variant -> base). Checked AFTER the id's own
	// measurement so adding a real measurement for a variant later simply
	// wins, with no edit here.
	if base := loudnessAliasFor(id); base != id {
		v, ok := instrumentLoudnessAmp[base]
		return v, ok
	}
	return 0, false
}
```

// An instrument with neither its own measurement nor a declared borrow falls
// back to DefaultAmplitude -- a silent level jump, never an error. Before this
// change 23 of 133 roster ids landed there, 18 of them only because the
// caller folded the id first. The alias map now covers those 18, so exactly
// these SIX are left, and each is a deliberate gap rather than an oversight.
//
// Naming them (instead of counting) means a new variant that forgets an alias
// fails with the id in the message.
func TestOnlyKnownInstrumentsFallBackToDefaultAmplitude(t *testing.T) {
	want := map[string]bool{
		"sub-bass": true, "sub-bass-1": true, // sub-bass was never measured
		"snare-ghost": true, "kick-tight": true,
		"hihat-pedal": true, "clap-tight": true,
	}
	for _, id := range BuiltinInstrumentIDs {
		if _, ok := loudnessAmp(id); ok {
			continue
		}
		if !want[id] {
			t.Errorf("%s has no resolvable loudness and no declared borrow; it will render at DefaultAmplitude", id)
		}
		delete(want, id)
	}
	for id := range want {
		t.Errorf("%s was expected to lack a loudness measurement but now has one; update this list", id)
	}
}

// The alias map must never point at an id that has no measurement of its own,
// or the borrow silently resolves to DefaultAmplitude anyway.
func TestLoudnessAliasTargetsAreMeasured(t *testing.T) {
	for id, base := range loudnessAliases {
		if _, ok := instrumentLoudnessAmp[base]; !ok {
			t.Errorf("%s borrows %s, which has no measured loudness", id, base)
		}
	}
}
```

### Task 2: Legacy-id aliases, so renames cannot break saved work

Renaming a shipped variant breaks any project, kit, bundle or favorites entry
that names the old id. No built-in template is affected (verified: no template
JSON references any shipped `-N` variant; templates only use *instance* ids
like `piano-grand-2`), but user projects on disk are.

The alias is applied at **registry level**, not at each call site — the
precedent is `EnsureInstanceInstrument`, which already "aliases the variant
onto the base's playable Instrument".

package audio

// legacyInstrumentIDs maps every retired instrument id to its current one.
//
// Ids are permanent in saved work: a project, kit, bundle or favourites entry
// records the id the user picked, so renaming a shipped instrument without a
// row here turns that row silent on load. Entries are APPEND-ONLY -- a row
// removed from this table is a project that stops working.
//
// Populated by the Phase 0 rename, which replaced meaningless ordinals
// (snare-1, snare-2) with names describing the sound.
var legacyInstrumentIDs = map[string]string{}

// LegacyInstrumentID resolves a retired instrument id to its current one,
// reporting false for an id that was never renamed.
func LegacyInstrumentID(id string) (string, bool) {
	current, ok := legacyInstrumentIDs[id]
	return current, ok
}
```
