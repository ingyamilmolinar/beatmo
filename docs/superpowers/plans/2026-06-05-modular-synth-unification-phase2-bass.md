# Modular Synth Unification — Phase 2: Bass Family Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Steps use checkbox syntax.

**Goal:** `drum-sub-bass` and `drum-bass-guitar` render byte-identically through the modular engine (all 42 oracle fixture cases), then their legacy C paths are deleted.

**Architecture decisions (pattern for ALL family phases 2–7):**

1. **Migrated recipes keep their legacy-named ParamDefs** (`fundamental`, `bass_sustain`, …, plus wired generic `pitch/decay/tone/drive/body`). The oracle fixture keys therefore stay valid verbatim, the Synth-tab UI is unchanged until Phase 8, and export/import param names don't churn per phase. The **per-family mapping function** (`bassRecipeToModular(p RecipeParams) ModularParams` in Go) translates legacy-named params → modular fields; it is simultaneously (a) the native render binding, (b) the platform-push translation, and (c) the future Phase-8 rename table.
2. **The oracle test is the byte gate and needs ZERO changes**: after rebinding, `NewRecipe(id).Render` flows through the mapping → `render_modular_p`; all fixtures must pass unchanged.
3. **POST stage**: the legacy `apply_post_params` pipeline (pitch resample → decay env → body → brightness → tone → drive, per-instrument `decay_rate`) is REQUIRED by every family. It is transplanted once, this phase, as a shared C function called by BOTH `drums.c` (unchanged behavior) and the modular engine — same compiled code ⇒ byte-identity by construction.
4. **`voice_freq_hz` override**: legacy fundamentals (45 Hz) are unreachable exactly via `220*2^x`; append a param that, when > 0, sets the modular voice freq to that exact Hz (0 = existing pow-derivation, byte-neutral).
5. **New slot sources are discrete parameterized stages**, but where the legacy float-op order fuses operations (e.g. `(fund + harm*mix) * ampEnv * attackBoost`), the source keeps that fused structure with every constant exposed as a param. Decomposing further would change op order ⇒ bytes (spec §2 forbids). This is the honest endgame shape: discrete parameterized SOURCES + shared global stages.
6. **−0.0 hazard**: `0.0f + (−0.0f) == +0.0f`, so accumulating a slot into the zeroed mix can flip a −0 sample produced by the legacy path. Rule: when the legacy osc stage wrote nothing (osc off / silent), the FIRST active gen slot ASSIGNS (`out[i] = v`), subsequent slots accumulate. The oracle fixtures are the arbiter.

**Ground truth** (from recon; verify at implementation):
- `render_sub_bass_internal` (drums.c:1967–2023): no noise; phase/phase2 init π/2 (doubles); per sample: `pitchEnv=exp(-40t)`, `freq=base*(1+bPitchE*pitchEnv)`, `phaseInc=2π*freq/sr`, `phase+=phaseInc` normalized to [0,2π); `fund=osc_wave(bWave,phase)`; `phase2+=2*phaseInc` normalized; `harm=osc_wave(bWave,phase2)`; `ampEnv=exp(-bEnvRate*t)`; `attackBoost=1+bAttack*exp(-60t)`; `mixed=(fund+harm*bHarm)*ampEnv*attackBoost`; `sat=tanh(mixed*1.2)`; `out[i]=(float)sat*0.95f`. Defaults: bHarm=0.08 bPitchE=0.15 bAttack=0.2 bEnvRate=2.0 bWave=0, fundamental 45 (bass_fund clamp [25,250]).
- `render_sub_bass_p` (drums.c:2515): post_config `{decay_rate=4.0, pitch=1, decay=1, drive=1, body=1}` (NO brightness, NO tone).
- `render_bass_guitar_internal` (drums.c:1856–1959): ma_noise seed 0; delayLen=sr/baseFreq clamp [2,4096]; init: delayLen noise draws through pluck LP (alpha=bPluck); per sample: 1 unconditional draw (stretch decision rnd>0.5 → filtered=0.5*(current+prev)*bSustain else current*bSustain — VERIFY exact reads/op order in source, including `prev` update), attack window (~8ms): 1 extra draw, `attack=atkNoise*exp(-400t)*bAttack`; `envGlobal=exp(-bEnvRate*t)`; `mixed=(current+attack)*envGlobal`; `out[i]=softsat((float)mixed*0.85f)`. Defaults: bSustain=.996 bPluck=.35 bAttack=.25 bEnvRate=1.8, fundamental 55.
- `render_bass_guitar_p` (drums.c:2507): post_config `{decay_rate=5.0, pitch=1, decay=1, drive=1, body=1, tone=1}` (NO brightness).
- `apply_post_params` + post helpers: drums.c:2047–2146 + synth_post.h (verify which file holds the bodies). Order: pitch resample → decay env `exp(-t*rate*(1/decayMul−1))` → body LP(120Hz 1-pole RC) → brightness HP → tone LP (tone<0 only) → drive `sp_saturate`.
- `osc_wave(wave, phase)` lives in drums.c (find it; it is needed by the analytic source — de-static/share it; drums.c keeps using the shared one, native goldens prove no drift).
- Render paths: `builtinFamilyRenderers` (synth_registry_entries_native.go:85–94) → `renderBassGuitarFam/renderSubBassFam` (synth_params.go:502–514). Instruments `bass-guitar`/`sub-bass` (+`-1` variants) bind via `builtinInstrumentRecipeBindings`. JS: audio.js RENDER_INFO `paramBlock:'bass'`, export map `'bass-guitar':'render_bass_guitar'`.
- Oracle keys: 21 per recipe (default + min/max over: generic wired + fundamental + family fields). `drum-sub-bass` has NO tone keys.
